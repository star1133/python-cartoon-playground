# สถาปัตยกรรมระบบแอนิเมชันโค้ดภาษา Python ทั่วไปแบบอัตโนมัติ (Generic Automatic Python Visualization)

เอกสารนี้อธิบายรายละเอียดการทำงาน สถาปัตยกรรม และมาตรฐานความปลอดภัยของระบบแอนิเมชันสำหรับโค้ดภาษา Python มาตรฐานทั่วไป (Arbitrary Standard Python) ภายใน `python-cartoon-playground`

---

## 1. ปรัชญาและแนวคิดหลัก (Core Philosophy: User Code First)

1. **User Code First**: ผู้เรียนสามารถเขียนโค้ดภาษา Python ทั่วไป (เช่น `x = 10; y = 20; total = x + y; print(total)`) ได้ทันทีโดยไม่จำเป็นต้องนำเข้าโมดูลพิเศษ (`playground_world`) หรือเรียกฟังก์ชันเฉพาะกิจ (`move_forward()`, `turn_left()`) ระบบจะสร้างแอนิเมชัน 3 มิติและคำอธิบายภาษาไทยให้โดยอัตโนมัติ
2. **Explicit World Lesson as Optional**: โหมดแผนผังโลกเกม 3D (World Mode) จะเปิดใช้งานเฉพาะเมื่อมีการเรียกใช้คำสั่งบทเรียนโลกที่มีการเคลื่อนไหวจริง (`action !== 'idle'`) เท่านั้น หากโค้ดทำงานมี world snapshot ที่มีสถานะ `'idle'` เพียงอย่างเดียว ระบบจะไม่ถือว่าเป็นโหมดโลก และจะแสดงผลในโหมด Generic Python Code เสมอ
3. **Truthful & Deterministic Replay**: ทุกสถานะในฉากถูกคำนวณและฟื้นฟูอย่างสัตย์ซื่อ (idempotent backwards seek) จากข้อมูล `TraceEvent` ที่บันทึกไว้จริง ไม่มีการคำนวณซ้ำหรือคาดเดาผลลัพธ์ย้อนหลัง

---

## 2. โมเดลข้อมูลและการเปลี่ยนผ่านสถานะ (Data-Driven Transition Model)

### 2.1 โครงสร้าง TraceEvent
การขับเคลื่อนแอนิเมชันอ้างอิงจากเหตุการณ์ใน Pyodide runtime (`src/runtime/types.ts` และ `public/python/tracer.py`):
- `seq`: ลำดับเหตุการณ์ที่เพิ่มขึ้นตามเวลาจริง
- `kind`: ประเภทเหตุการณ์ (`'line'`, `'call'`, `'return'`, `'stdout'`, `'stderr'`, `'exception'`)
- `line`: บรรทัดที่กำลังประมวลผล
- `locals`: ตัวแปรในเฟรมปัจจุบันที่ผ่านการ serialized อย่างปลอดภัย (`{type, value, id}`)
- `stack`: คอลสแตกปัจจุบัน (`string[]`)
- `text`: ข้อความผลลัพธ์ (เช่น ค่าคืนของฟังก์ชัน, stdout, หรือ exception message)

### 2.2 การตรวจจับความแตกต่าง (Diff Tracking)
`reduceSceneState` ตรวจสอบความแตกต่างระหว่างตัวแปรในเหตุการณ์ก่อนหน้า (`prevLocals`) และปัจจุบัน:
- `isNew`: ตัวแปรที่เพิ่งถูกสร้างขึ้นใหม่ในรอบนี้
- `isChanged`: ตัวแปรที่มีการเปลี่ยนแปลงค่าจริง
- `lastChangedVar`: ชื่อตัวแปรล่าสุดที่ได้รับการอัปเดต เพื่อให้ตัวละครหันหน้าและก้าวไปมีปฏิสัมพันธ์กับสถานีตัวแปรนั้น

### 2.3 การอธิบายโค้ด (Pre-line Phrasing & Completed Diff)
ตามหลักการศึกษาโปรแกรมมิ่งที่ถูกต้อง:
- **Pre-line Statement**: เมื่อเหตุการณ์อยู่ที่บรรทัดการกำหนดค่า คำอธิบายจะใช้คำว่า **"กำลังจะ..."** (เช่น *"กำลังจะกำหนดค่าให้กับตัวแปร 'x'"*) เนื่องจากในจังหวะนั้นคำสั่งยังไม่ถูกประมวลผลเสร็จสิ้น
- **Completed Assignment**: เมื่อคำสั่งทำงานเสร็จในบรรทัดถัดมา การเปลี่ยนแปลงค่าจะถูกรายงานจากผลต่าง (Diff) จริง (เช่น *"กำหนดค่า '10' ให้กับตัวแปร 'x' เรียบร้อยแล้ว"*)

## 3. องค์ประกอบภาพ 3 มิติ (3D Isometric Components)

เวทีจำลองข้อมูลประกอบด้วยโมดูลต่อไปนี้:
1. **สถานีกล่องตัวแปร (Variable Stations Pool: สูงสุด 12 กล่อง)**:
   - แท่นวางทรงไอโซเมตริกสำหรับแต่ละตัวแปร พร้อมป้ายชื่อตัวแปรและประเภท (`[int]`, `[str]`, `[list]`, ฯลฯ)
   - แผ่นโทเคนแสดงค่า (Value Token) ที่เคลื่อนที่เลื่อนลงสู่กล่องเมื่อมีการเปลี่ยนแปลงค่า พร้อมวงแหวนแสงนีออน (Glow Ring)
   - ป้ายแจ้งเตือนที่ซื่อสัตย์ `+N omitted` เมื่อมีตัวแปรเกินงบประมาณ 12 ตัวแปร
2. **การแปลงข้อมูลคอนเทนเนอร์อย่างปลอดภัย (Safe Value Parser)**:
   - จัดการข้อมูลประเภท `list`, `tuple`, `dict`, `set`, และ Custom Class Object จากสตริงที่ถูก serialized โดยปราศจาก `eval()` หรือ dynamic code injection อย่างเด็ดขาด
   - แสดงผลองค์ประกอบย่อยเป็นชิปรายการ (เช่น `[0]: 10`, `[1]: 20` หรือ `'debug': True`)
3. **สถานีคอลสแตก (Call Stack Station)**:
   - หอคอยแสดงแผ่นเฟรมการทำงานของฟังก์ชัน (Stack Frames) ทางฝั่งซ้ายของเวที
   - ตัวละครทำท่าร่ายคาถา (`cast`) เมื่อเกิด `'call'` และทำท่าฉลอง (`celebrate`) เมื่อเกิด `'return'` พร้อมแสดงโทเคนค่าที่คืนออกมา
4. **ลูปแทร็ก (Loop Track Circuit)**:
   - วงแหวนสะท้อนการวนซ้ำรอบเวที ตรวจจับจากการรันบรรทัดเดิมซ้ำใน trace event (`lineVisitCounts`)
   - แสดงแสงเรืองรองและการก้าวเดินของตัวละครตามรอบการวนซ้ำ
5. **สถานีเอาต์พุตคอนโซล (Stdout Screen)**:
   - แผงจอแสดงผลทางฝั่งขวาสำหรับข้อความที่พิมพ์ผ่าน `print()` หรือ stdout
6. **การแสดงผลข้อผิดพลาด (Exception Alert)**:
   - แสดงสถานะข้อผิดพลาดตามความเป็นจริงจากเหตุการณ์ `'exception'` (เช่น `ZeroDivisionError: division by zero`) โดยไม่มีการกุข้อความขึ้นมาเอง

## 4. ประสิทธิภาพและการจัดสรรหน่วยความจำ (Performance & Craft Floor)

1. **Zero Per-Frame Geometry Allocations**:
   - Geometries, Materials, และ Textures ทั้งหมดถูกสร้างขึ้นครั้งเดียวในรอบเริ่มต้น (`createVariableStage`, `createCharacterMesh`) และนำกลับมาใช้ใหม่ผ่าน Object Pooling
   - ไม่มีคำสั่ง `new THREE.*` ใน render loop (`requestAnimationFrame`)
2. **Local 2D CanvasTexture**:
   - ข้อความบนป้ายชื่อและค่าตัวแปรถูกวาดลงบน 2D `<canvas>` ในหน่วยความจำเครื่อง และอัปเดตผ่าน `texture.needsUpdate = true`
   - ไม่มีการดาวน์โหลดฟอนต์ภายนอกหรือพึ่งพาเครือข่ายอินเทอร์เน็ต
3. **การปลดปล่อยทรัพยากร (Resource Disposal)**:
   - มีการเรียก `dispose()` ในทุก Mesh, Geometry, Material, Texture, และ ResizeObserver อย่างสมบูรณ์เมื่อถอดคอมโพเนนต์

---

## 5. การเข้าถึงและการรองรับอุปกรณ์ (Accessibility & Fallback)

1. **Semantic DOM Alongside Canvas**:
   - มี Accessible Variable Dock แสดงชิปตัวแปรใน DOM จริงเคียงข้าง Canvas
   - มี Screen Reader Live Region (`role="status"`, `aria-live="polite"`) สำหรับการประกาศภาษาไทยทุกขั้นตอน
2. **2D WebGL Fallback View**:
   - หากเบราว์เซอร์ไม่รองรับ WebGL หรือเกิดข้อผิดพลาดในการเรนเดอร์ ระบบจะสลับไปยังโหมดการแสดงผล 2 มิติที่ชัดเจนทันที
   - การ์ดข้อมูลใน 2D Fallback ให้ข้อมูลตัวแปร คอลสแตก และลูปครบถ้วนตามความจริง
3. **Reduced Motion**:
   - รองรับ `prefers-reduced-motion: reduce`: ตัวละครและโทเคนจะย้ายตำแหน่งทันทีโดยไม่มีแอนิเมชันกระโดดหรือหมุนวน ป้องกันอาการวิงเวียนของผู้ใช้

---

## 6. ข้อจำกัดของระบบ (Known Limitations)

1. **ขีดจำกัดจำนวนตัวแปรในฉาก 3 มิติ**: แสดงผลได้สูงสุด 12 ตัวแปรบนเวทีไอโซเมตริก ตัวแปรส่วนที่เหลือจะถูกนับรวมและแสดงป้ายแจ้งเตือน honest `+N omitted`
2. **โครงสร้างข้อมูลขนาดใหญ่มาก**: สำหรับลิสต์หรือดิกชันนารีที่มีสมาชิกจำนวนมาก ระบบจะตัดทอนและแสดงผลเฉพาะ 6-8 รายการแรกพร้อมสัญลักษณ์ `...` เพื่อรักษาความเร็วและความปลอดภัยของหน่วยความจำ
3. **โมดูลภายนอกเฉพาะทาง**: ออบเจกต์จากไลบรารีภายนอกที่ไม่มีตัวแทนภาพเฉพาะจะแสดงเป็น Class Object Badge (เช่น `<User #abcd>`) โดยอ้างอิงจากคลาสและ ID อย่างปลอดภัย
